# Phase 4 生日终幕与首映：既有视觉世界的扩展

## Overview

沿用「深夜的私人胶片工作台」，落实 [finale-contract.md](finale-contract.md) 与 [premiere-contract.md](premiere-contract.md)。首映是安静的电影邀请；末卷回到胶片、灯暗、字幕停顿，最后让生日信获得完整的阅读时间。此处记录已实现的局部扩展，不另建视觉世界。

[DESIGN.md](../DESIGN.md) 与 [design.json](design.json) 原样保留。它们是 Phase 2 规范快照，未收录 Phase 3/4 的阅读纸面、共享声音、银幕/终幕/首映组件及局部布局；「没有长文阅读样式」「声音仅为未配置提示」、横屏预览按钮（38px）的描述分别已有长文、可配置音频与（44px）按钮的后续覆盖。Phase 3 细节见 [screening-design.md](screening-design.md)。本次没有把这些差异静默写回规范。

## Colors

背景、主要文字与器材标记继续使用规范的炭墨、奶油、黄铜和酒红。首映使用从低亮酒红到炭墨的径向暗光，终幕则由胶片工作台的灯光过渡到炭墨黑场；不增加高饱和庆祝色。

信件复用故事纸面的局部材料色：旧纸（`#e4dac7`）、深褐正文（`#3b302a`）、褐色辅助信息与焦点（`#755f50`）。纸页按钮 hover / active 为更深的褐黑（`#211d19`），避免继承暗场按钮的近白悬停色。这些是附着于纸张的源码值，没有新增为全局 token。缺省信件提示采用较浅褐色（`#806855`）。

## Typography

继续使用本地 Bodoni Moda / Manrope 与系统中文后备。首映片名和终幕字幕是衬线电影标题；倒计时使用 Manrope 与 `tabular-nums`，避免秒数改变引起宽度跳动。信件和片尾标题保留斜体，正文以阅读为先。

| 角色       | 桌面                        | 低矮横屏    | 手机竖屏    |
| ---------- | --------------------------- | ----------- | ----------- |
| 首映片名   | `clamp(57px, 8.5vw, 112px)` | 43px        | 57px        |
| 倒计时数字 | `clamp(38px, 5vw, 65px)`    | 36px        | 42px        |
| 生日祝福   | `clamp(52px, 6vw, 84px)`    | 43px        | 58px        |
| 信件标题   | 34px / 1.35                 | 24px / 1.35 | 29px / 1.35 |
| 信件正文   | 15px / 2.15                 | 13px / 1.95 | 15px / 2.05 |
| 片尾标题   | `clamp(38px, 4.5vw, 64px)`  | 35px        | 42px        |

正文最大行长（65ch），按空行分段，保留段内换行，连续长字符自动折行。日期仅在配置存在时显示，落款优先 `signature`、其次 `credit`；未填署名展示明确待填提示，主演回退到现有片头 `starring`。默认 `finale.letter`、真实姓名和署名均留空，通用礼物文案不是私人记忆。

## Layout

断点沿用工作台：（max-height: 550px）且横屏；（max-width: 700px）且竖屏。终幕外层可滚动，页眉 sticky，底层工作台锁定；纸页文章和片尾姓名区各有自身滚动，正文不会推动纸页继续按钮离开纸页底部。

| 场景       | 桌面                                                                          | 低矮横屏                                                 | 手机竖屏                                                                 |
| ---------- | ----------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| 首映邀请   | 中央内容最大宽（760px），外框内缩（36px），头尾信息退到边缘                   | 外框（15px）、片名和倒计时纵距压缩，倒计时宽（340px）    | 外框（18px），倒计时占可用宽度，保持纵向留白                             |
| 终幕页眉   | 高（96px），片名居中，返回与声音分列                                          | 高（52px），保留中央片名                                 | 高（78px），隐藏中央片名，返回与声音保留                                 |
| 收卷舞台   | 宽取（1100px）与（92vw）较小值，高（300px）；胶卷（250px）                    | 舞台高（230px）、胶卷（180px），控制位于底边             | 舞台宽（96vw）、高（240px）、胶卷（190px），底片可在边缘延伸             |

收卷外层 `.rewind-anchor` 负责百分比居中，内部 `.rewind-stage` 只承担动画位移、缩放与透明度；两种 transform 不互相覆盖。旋转依 CSS 重新布局，React 的当前阶段不因横竖屏改变而重置。返回、暂停、跳过与声音处于机械舞台之外。

## Elevation & Depth

复用实体胶卷、琥珀齿孔与暖色底片投影。收卷使用末卷最后最多三个画幅，作为装饰性电影回收镜头；其中照片 `cover` 并做旧，正式播放器仍然 `contain` 全幅显示。

纸页投影（`15px 27px 40px #09070966`）延续工作台右下受光关系；片尾和首映用极淡黄铜线框与暗光建立层次，不叠加卡片或新装饰素材。未新增交付栅格素材，沿用六张已有许可记录的演示图；出处见 [assets.md](../docs/assets.md)。新增 PNG 为实际浏览器截图。

## Shapes

纸张与片尾边框保持直边，信件页眉和页脚用细褐线分隔。首映细框的对角短角标像放映定位标记；沿用文本按钮、细线开始按钮与既有音乐控制，不引入庆祝徽章、卡片系统或新的大圆角面板。

## Components

### 首映门禁与状态

`page.tsx` 在服务端判断 `getPremiereState`：正常配置为（`2027-02-07T00:00:00+08:00` / `Asia/Shanghai`）；未到时只渲染 `PremiereGate`，不将章节、照片清单或信件传入浏览器。显式启用但日期、偏移或时区无效时保持关闭；旧配置缺省 `premiere` 或明确 `enabled: false` 则开放。显示时区不替代开放时刻中的显式 UTC 偏移。

`PremiereGate` 包含锁定邀请、禁用入口、归零后的确认、服务端开放、连接失败/重试和时间待安排状态。显示倒计时以服务端时间加 `performance.now()` 推进，每秒更新；每（30s）、页面重新可见和归零时请求不缓存的 `/api/premiere`。客户端归零只触发校验，服务器返回 open 才刷新进入片头；不会通过客户端时钟或查询参数自行解锁。

`PREMIERE_PREVIEW=1` 是服务端运行开关；作者只可在绑定 `127.0.0.1` 的独立本机实例使用，不是访客 URL 或管理员认证。代码不因环境变量存在而自动限制监听地址，启动约束见 [premiere-guide.md](../docs/premiere-guide.md)。`public` 演示媒体仍可直接访问，当前门禁没有实现媒体 ACL。

### 终幕状态与运动

`FilmArchive` 在最后一个有照片章节结束后进入 `BirthdayFinale`；普通章节继续进入手动章间卡。终幕状态是 `intro → letter → credits`，重读入口直接进入 letter。序幕内部节拍是 `rewind → question → answer → continued`：

| 时间     | 实际行为                                                              |
| -------- | --------------------------------------------------------------------- |
| 0s 起    | 舞台（0.65s，`power3.out`）落定；胶卷往返（0.8s × 2，`power2.inOut`） |
| 0.2s 起  | 底片 scaleX 收至 0（1.45s，`power3.inOut`）                           |
| 0.65s 起 | 灯光退去（1.05s，`power2.inOut`）                                     |
| 1.1s 起  | 舞台淡出并缩小（0.7s）                                                |
| 1.5s     | THE END? 淡入（0.5s）；2.25s 起淡出（0.35s）                          |
| 2.75s    | NO. 淡入（0.4s）；3.35s 起淡出（0.3s）                                |
| 3.85s    | TO BE CONTINUED... 淡入（0.65s，`power3.out`）；5.55s 起淡出（0.45s） |
| 6.1s     | 进入生日信；祝福（0.8s）、纸页（1s，`power3.out`）入场                |

节拍时刻来自 `src/lib/finale.ts`，其余时长来自 `BirthdayFinale` 当前时间线；没有把 Phase 2 的默认运动常量误写成这里的运行值。未显式传 ease 的 tween 使用 GSAP 默认值。

手动暂停、页面后台或打开声音设置都会暂停 intro 时间线；继续从暂停处推进。跳过直接读信；返回或 Escape 取消并清理。信件没有阅读倒计时，只能主动进入片尾；片尾也不自动返回。片尾各文字组以（0.75s，stagger 0.2s）入场，操作延迟（0.8s）后淡入（0.6s），保持可手动重读。

### 阅读、声音与可访问性

信件使用普通 React 文本节点，不执行 HTML；空行分段，文章可聚焦并独立滚动，结尾署名与纸页继续按钮可达。长文测试中的脚本字串是有意验证纯文本的 fixture，不是用户信件。

终幕复用 `useScreeningDialog`：`role=dialog`、`aria-modal`，Tab 约束、底层 inert、滚动锁定/恢复，初始焦点在返回；进入信件/片尾将焦点放到标题，但不抢走音乐面板中的焦点。音乐面板先处理自己的 Escape。卸载回收 GSAP context、媒体查询与页面可见性监听。

`prefers-reduced-motion` 初始即直达信件；运行中切换为 reduce 也跳过尚未结束的序幕，禁用信件与片尾入场 tween。阅读、片尾和导航仍可操作。字体、纸张、静态颗粒仍保留。

声音由 `FilmArchive` 内同一控制器和原生 Audio 承接，终幕来源为 `music.finale`，否则回退 `music.archive`；intro、letter、credits 与返回之间保留音量/静音，照片或序幕暂停不自动停止背景音乐。音源失败不阻断阅读；默认 JSON 无正式音乐，显示 SOUND OFF。减少动态效果与声音设置相互独立。

## Do's and Don'ts

- Do 将机械收束留在序幕，将阅读和片尾推进交给用户。
- Do 保持纸页深色按钮的默认、悬停、按下与焦点对比；同时检查三种构图。
- Do 保留未知姓名、落款和私人信件为空，明确区分默认祝福、演示照片与测试排版文本。
- Do 将首映门禁、媒体授权、浏览器观影记录和后台内容持久化分别验收。
- Don't 用浏览器时钟、URL 参数或前端隐藏替代服务端开放判定。
- Don't 将本机预览开关用于公开服务，或将 public 演示图片声称为受保护私有媒体。
- Don't 将测试通过、截图或本文写成独立评审通过、真实设备/音频验收或公开部署完成。
